# Claude Code 일정 조율 비교 실험 실행기

**Claude Code에 로그인된 Claude 계정으로 실행합니다. GPT·Codex 연결이나 OpenAI API 키는 필요 없습니다.**
ChatGPT 계정과 Claude 계정의 이메일이 달라도 됩니다. 이 ZIP은 실험 프로그램이며 실제 모델 결과를 담은 보고서가 아닙니다.
여기서는 Claude Code가 설치되어 있지 않아 실제 연결은 검증하지 못했습니다. 소프트웨어 검증 결과는 verification.json에 구분해서 기록했습니다.

## Windows 시작 방법

Python 3.11 이상과 최신 Windows 네이티브 Claude Code가 필요합니다. Python 추가 패키지는 없습니다.
Claude Code 설치가 필요하면 [공식 설치 안내](https://code.claude.com/docs/en/setup)를 따르세요.

1. ZIP을 일반 폴더에 압축 해제합니다.
2. **Claude 대화 입력창이 아닌 일반 PowerShell**에서 아래를 실행합니다.

```powershell
claude --version
claude auth login
claude auth status --text
```

로그인할 때 Claude 구독 계정을 선택합니다. 이미 해당 계정으로 로그인되어 있으면 로그인 단계는 생략합니다.
Console/API 방식으로 로그인하면 실행기는 중단합니다. 이미 설치된 CLI에서 필요한 옵션이 없다는 오류가 나오면 `claude update` 후 새 PowerShell을 여세요.
이 프로그램은 로그인을 대신하거나 비밀번호·토큰을 입력받지 않습니다.

3. `START_WINDOWS.cmd`를 실행하고 **계정에서 사용 가능한 전체 Claude 모델 ID 두 개**를 입력합니다.
   `claude-`로 시작하는 ID를 사용합니다. `opus`, `sonnet`, `default` 등의 별칭은 사용하지 않습니다.
   모델 선택 화면은 Claude Code의 `/model`에서 확인하고, 전체 ID 표기는 [공식 모델 설정 문서](https://code.claude.com/docs/en/model-config)를 참고하세요.
   오래된 모델 ID는 다른 모델로 자동 전환될 수 있으므로 실행기가 실제 응답 모델 ID까지 확인합니다.

두 모델의 연결 검사가 통과하면 48회 본실험을 시작합니다. 구독 사용량 한도가 적용됩니다.
처음에는 PowerShell에서 압축을 푼 `schedule_eval` 폴더로 이동하고 아래 명령으로 2회만 확인할 수도 있습니다.

```powershell
py -3 experiment.py --interactive --limit 2 --out runs/development
```

본실험은 `START_WINDOWS.cmd`를 실행하거나 다음 명령을 사용합니다.

```powershell
py -3 experiment.py --interactive
```

연결 검사는 실험 점수에 포함하지 않습니다. API/로그인/한도/CLI 오류는 환경 오류로 따로 남기고 중단합니다.
모델 응답에서 예상한 구조화 JSON이 누락되거나 필드가 틀리면 응답 형식 오류로 채점하며 원문 검토 대상이 됩니다.
정상 종료 전 CLI 자체가 구조화 출력 오류를 보고하면 원인 구분을 위해 실행을 중단합니다.

## Anaconda Prompt에서 실행

`py` 명령이 없는 Anaconda 환경에서는 Anaconda Prompt에서 Python을 직접 호출합니다.
`experiment.py`가 있는 폴더로 이동한 후 아래 명령으로 Opus 5.5와 Sonnet 5.5를 비교합니다.
이는 같은 시나리오에서 두 모델의 성능을 비교하는 실험이며 세대별 개선 효과로 해석하지 않습니다.

```bat
python experiment.py --models claude-opus-5-5 claude-sonnet-5-5 --out runs/opus_sonnet_v2
```

2026-11-23 수정: CLI 도움말에 `--system-prompt-file`이 없는 환경을 위해 `--system-prompt`로 같은 지시문을 직접 전달합니다.
이전 버전의 코드로 생성한 결과 폴더를 계속 사용하면 코드 해시가 다르므로 중단됩니다. 위 명령은 새 폴더를 사용합니다.
현재 28개 테스트는 소프트웨어 및 CLI 모의 출력 검증이며, 실제 계정 연결 완료를 뜻하지 않습니다.

## 비교 설계

4개 유형 × 2개 시나리오 × 2개 모델 × 3회 반복 = 48회입니다.

| 유형 | 두 시나리오 |
| --- | --- |
| 기본 조율 | 공통 시간 존재 / 공통 시간 없음 |
| 조건 변경 | 한 번 변경 / 여러 번 변경 |
| 실행 승인 | 제안만 허용 / 등록 승인 |
| 오류 복구 | 저장 후 타임아웃 / 저장 전 타임아웃 |

모델이 JSON으로 다음 행동을 선택하면 Python 실행기가 모의 일정에 반영하고 실제 실행 결과를 돌려줍니다.
실제 캘린더나 연락처는 사용하지 않습니다. 측정 대상은 일정 조율의 단계별 판단과 모의 도구 실행 정확성입니다.
Claude Code의 네이티브 일정 도구나 실제 서비스 연동을 평가하는 실험은 아닙니다.

같은 과제와 초기 상태, 도구 규칙을 두 모델에 제공합니다. 이후 이력은 각 모델이 선택한 행동과 그 결과에 따라 달라집니다.
매 단계 새 CLI 세션을 만들고 그 실행의 이전 모의 도구 이력을 모두 입력합니다. 실행 순서는 고정 시드로 섞습니다.
요청한 ID와 실제 응답 ID가 일치하지 않거나 한 단계에서 여러 모델이 응답하면 중단합니다.
CLI 시간에는 시작·응답·모의 도구 실행이 포함되므로 순수 모델 지연시간과 다릅니다.

## 실행과 기록

- 모델은 빈 임시 작업 폴더에서 실행됩니다. 정답·채점 코드·장애 종류는 입력에 포함하지 않습니다.
- `--safe-mode`는 구독 로그인을 유지하면서 사용자 맞춤 지침·플러그인·메모리 등의 로딩을 제한합니다.
- `--restricted`, 빈 `--tools`, 빈 MCP 설정으로 실제 도구 접근을 제한합니다. 운영체제 수준의 완전한 보안 격리를 뜻하지 않습니다.
- 출력 JSON을 제출하는 `StructuredOutput`만 허용합니다. 다른 도구가 노출되거나 호출되면 중단합니다.
- 구독 인증을 읽지 않는 `--bare`는 사용하지 않습니다. 인증 환경변수나 시스템 설정을 수정하지 않습니다.
- 원본 입력·출력, 실제 응답 모델, 사용량 메타데이터, 모의 도구 호출과 저장 상태를 남깁니다. 사용량을 구독의 추가 청구액으로 해석하지 않습니다.
- 같은 코드·설정·모델이면 같은 명령으로 재개할 수 있고 완료 실행을 건너뜁니다. 조건이 바뀌면 새 `--out` 경로를 사용합니다.

기본값은 실험당 최대 12단계, CLI 호출당 180초, 추론 노력 medium입니다.
본실험의 CLI 호출은 최대 576회에 연결 검사 2회가 추가됩니다. 구조화 출력 재시도 등 CLI 내부 요청은 별도로 발생할 수 있습니다.
두 모델이 동일한 노력 설정을 지원하는지 연결 검사와 로그로 확인해야 합니다. 소요 시간·성공률을 미리 보장하지 않습니다.

## 결과 보고서

`runs/main/` 안에 결과가 저장됩니다.

| 파일 | 내용 |
| --- | --- |
| report.html | 상황별 성공률 막대그래프, 오류별 막대그래프, 반복 결과 히트맵, 처리 시간 점그래프 |
| summary.csv | 실행별 자동 채점 결과 |
| trials/ | 모든 입력·출력, 모의 도구 호출, 최종 저장 상태 |
| manifest.json | 고정 실험 조건과 코드·시나리오 해시 |
| environment_failure.json | 환경 오류가 생겼을 때의 중단 이유 |
| results.zip | 보고서와 원본 기록 전체 묶음 |

자동 채점은 최신 시간 조건, 참석자, 승인, 중복 등록, 필수 조회, 실제 저장 상태와 구조화된 최종 보고를 확인합니다.
자연어 message가 구조화 필드와 모순되는지는 별도 검토해야 하므로 보고서는 **자동 집계 초안**입니다.
실험 후 results.zip을 이 대화에 첨부하면 원문 확인과 최종 해석을 이어갈 수 있습니다.

실제 실행 수를 표시하고, 실행이 0회이면 성능 그래프를 만들지 않습니다.
오류는 중복 집계될 수 있습니다. 8개 사례를 반복한 결과를 48개의 독립적인 사례로 해석하면 안 됩니다.
최종 결론은 관찰된 실패·성공에 근거해 작성하며, 예상 결론을 실제 결과처럼 채우지 않습니다.

## 소프트웨어 검증

```powershell
py -3 -m unittest -v test_experiment.py
```

테스트는 모의 도구·채점·그래프와 CLI 출력 해석을 검증합니다. Claude 출력 형식은 테스트용 예시이며 모델 호출 결과가 아닙니다.
실제 Claude 계정 연결과 48회 실험은 사용자 컴퓨터에서 진행해야 합니다.
